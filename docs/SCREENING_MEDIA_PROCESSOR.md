# Private screening media processing

The Screening recording editor uses a local FFmpeg/ffprobe adapter. Original recordings remain unchanged. Exports re-encode the selected segments, in their chosen order, to H.264/AAC MP4. Each segment can retain its original audio or be muted. A recording without audio exports without an audio track. The adapter removes source metadata and chapters; MP4 technical/container metadata is generated by the encoder.

Install FFmpeg with the `libx264`, `aac`, and `libmp3lame` encoders and put both `ffmpeg` and `ffprobe` on the API server's PATH. Optional `SCREENING_FFMPEG_PATH` and `SCREENING_FFPROBE_PATH` values select server-owned executables. These are operator settings, never request parameters. After changing capabilities, restart the server to refresh its cached capability check.

Inputs must be private regular local MP4 files, at most 250 MiB and 30 minutes, with one video stream and at most one audio stream. Video is bounded to 3840 × 2160 and 120 fps. Edits support 1–12 ordered segments, each at least 0.1 seconds, and at most 30 minutes of combined output. The API further limits an edit's combined duration to the source duration. FFmpeg decodes and re-encodes boundaries; they are accurate to the media's sample/frame resolution, not an assertion of arbitrary subframe accuracy. Output is capped at 250 MiB and its duration is verified before delivery. The source is never overwritten.

Subprocesses receive argument arrays without a shell, fixed MP4 demuxing, disabled external data references, and a local-only protocol allowlist. Adapter operations are bounded to 15 minutes (the API imposes a 10-minute job deadline), use two encoding threads, terminate on cancellation, and remove their temporary files in `finally`. All scratch audio/video lives beneath the caller's private job directory so the API's durable cleanup also removes it after an interrupted server process. The API layer owns authorization, source retention checks, queue/concurrency limits, and durable cleanup of stored derivatives. API callers must use `status(workspaceId)` before starting provider work; the low-level adapter's `align` method does not identify the workspace itself.

## ASR-derived word timing

Word timing is an explicit transcription action that sends compressed mono 16 kHz MP3 audio to the configured speech provider. It reuses `OPENAI_API_KEY` and `OPENAI_TRANSCRIPTION_BASE_URL` (default `https://api.openai.com/v1`). The existing `LLM_WORKSPACE_IDS` allowlist takes precedence over `OPENAI_WORKSPACE_IDS`; an explicitly empty list enables no workspace. Text gateway credentials alone do not enable speech. Provider usage may be billable.

`SCREENING_WORD_ALIGNMENT_MODEL` defaults to `whisper-1` independently of `OPENAI_TRANSCRIPTION_MODEL` and `LLM_MODEL`. The request uses `/audio/transcriptions`, `response_format=verbose_json`, and `timestamp_granularities[]=word`. OpenAI documents word timestamp support for `whisper-1`; other configured endpoints/models must support that same response contract. See the [official speech-to-text guide](https://developers.openai.com/api/docs/guides/speech-to-text) and [transcription API reference](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create), checked on 2026-10-13.

The server validates provider word counts, response size, ordering, and time bounds against the actual recording. The matching helper retains every original transcript character. A word receives its provider timestamp only when its normalized spelling appears exactly once in that transcript turn and in the provider words contained in the turn's known timing bounds, with consistent ordering. Overlapping turns, repeated or missing words, unsupported tokenization, changed spelling, and missing utterance timing remain untimed. Punctuation and spacing remain untouched. This deliberately conservative matching is **ASR-derived word timing**, not phonetic forced alignment, exact acoustic boundaries, a corrected transcript, or evidence that an unmatched word was not spoken. It does not infer timings by evenly dividing utterances.

The input container and video must start at timeline zero (within 1 ms); unsupported origins are rejected instead of silently shifting transcript offsets. A positive initial audio-track delay is preserved by padding leading silence before transcription and before clip trimming. Zero-length, overlapping, out-of-order, or out-of-bounds provider word timings are rejected. ASR matching does not replace the transcript's existing timing or text when validation fails.

## Verification

`npx tsx --test tests/server/screening-media-processor.test.ts` generates local synthetic media and tests the real codecs, duration, ordered audio muting, private output permissions, source preservation, input validation, cancellation, and no-audio behavior. Provider tests inject an in-memory HTTP response; they never call a speech service. The tests skip media-dependent cases if executables are unavailable, so deployment/CI validation must install FFmpeg to establish actual processing coverage. Pure matching tests always run.
