# Source-to-ArkOffer parity matrix

This matrix records the scope of the **local full-stack reconstruction**, reviewed on 12 October 2026. **100% Metaview parity is not achieved.** An implemented local workflow can still cover only part of the corresponding source product. No percentage is assigned because neither the private backend nor every source account/plan state was observable.

Evidence categories and collection limits are in [RECONSTRUCTION.md](RECONSTRUCTION.md). Public source pages establish advertised behavior; native Chrome observations directly informed notes, templates, and the demo workspace. The local implementation and tests establish what ArkOffer does.

Status terms:

- **Implemented locally:** a working local behavior with persistence or a functioning public interaction.
- **Partial:** useful behavior exists, with material source capabilities missing.
- **Provider-gated:** an actual provider path exists but needs configuration; real provider operation is not established by mocked tests.
- **Not implemented:** no working path exists; a landing page, setup notice, or draft editor is insufficient evidence.

## Validation interpretation

The browser suite exercises signup through persistent API writes, note editing, public sharing, archive/collection behavior, templates, candidates, sequence drafts, applications/jobs, screening drafts and published responses, and reports. API tests cover additional authorization and boundary conditions that are difficult to infer from screenshots. Marketing smoke checks exercise public navigation, resource search, pricing controls, form persistence and responsive layout.

Final local verification passed **29 API tests (21 core and eight screening), 11 browser tests, the production build, and formatting checks**. The browser suite includes the public candidate response flow and regressions for settings-tab isolation, delayed template saves, generation failure, and late microphone permission after dialog closure. Microphone permission is simulated in that regression; real capture and live paid-provider execution remain unverified.

No test establishes external provider connectivity, original-service behavior, microphone capture, automated hiring quality, production scalability, complete accessibility conformance, or exact source visual equality. A passing local test/build and passing GitHub checks are delivery evidence for this reconstruction; they do not close the missing features listed above.

The largest work remaining for the requested full clone is the external-service layer and team model: meeting capture, calendar/ATS OAuth, candidate data and enrichment, outreach execution, voice/video screening and delivery, multi-user permissions, fillmore automation, billing/credits, and enterprise operations. These are implementation projects, not hidden toggles in the delivered application.
