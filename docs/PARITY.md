# Source-to-ArkOffer parity matrix

This matrix records the scope of the **local full-stack reconstruction**, reviewed on 12 October 2026. **100% Metaview parity is not achieved.** An implemented local workflow can still cover only part of the corresponding source product. No percentage is assigned because neither the private backend nor every source account/plan state was observable.

The fresh signed-in, feature-by-feature audit is in [SOURCE_REVIEW.md](SOURCE_REVIEW.md). Evidence categories and collection limits are in [RECONSTRUCTION.md](RECONSTRUCTION.md). Public source pages establish advertised behavior; native Chrome observations directly informed notes, templates, and the demo workspace. The local implementation and tests establish what ArkOffer does.

Status terms:

- **Implemented locally:** a working local behavior with persistence or a functioning public interaction.
- **Partial:** useful behavior exists, with material source capabilities missing.
- **Provider-gated:** an actual provider path exists but needs configuration; real provider operation is not established by mocked tests.
- **Not implemented:** no working path exists; a landing page, setup notice, or draft editor is insufficient evidence.

## Validation interpretation

The browser suite exercises signup through persistent API writes, note editing, public sharing, archive/collection behavior, templates, candidates, sequence drafts, applications/jobs, screening drafts and published responses, and reports. API tests cover additional authorization and boundary conditions that are difficult to infer from screenshots. Marketing smoke checks exercise public navigation, resource search, pricing controls, form persistence and responsive layout.

The current test suites include the original notes/document/screening workflows and the added team, account, permission, calendar, provider, outreach, billing, assistant, job-draft, application-evidence, report-column and note-edit boundaries. Final executed totals and CI results are recorded in the delivery PR after the combined suite finishes. Microphone permission tests use simulated streams; real capture remains unverified. A bounded, isolated synthetic run exercised the configured live text model through job draft/apply, note preview/apply/version, application evidence review and queued report extraction/export. This does not establish continuous provider reliability or live operation of other integrations.

Mock-based tests do not establish external provider connectivity; the bounded live text-model check establishes only the exercised synthetic paths. Neither establishes original-service behavior, microphone capture, automated hiring quality, production scalability, complete accessibility conformance, or exact source visual equality. A passing local test/build and passing GitHub checks are delivery evidence for this reconstruction; they do not close the missing features listed above.

The largest remaining implementation gaps are comprehensive web/market research and source-scale discovery, real-time voice/video screening agents, rich media editing, autonomous Slack/fillmore recruiting workflows, additional ATS and mailbox integrations, automatic NLP report construction and subscriptions, CV ingestion/AI applicant ranking, external job publishing, usage/credit entitlements, and enterprise SSO/SCIM/retention controls. Implemented adapters also require operator configuration, provider approval where applicable, and live end-to-end validation before they are operational. The repository does not reproduce the source's private models or backend.

## Current provider boundaries

Voice screening uses explicit consent, bounded audio, candidate correction, linked transcript evidence and optional one-question clarification. Enrichment uses a fixed professional-data endpoint and requires proposal review; it does not crawl profiles. The separate Sourcing adapter offers bounded PDL candidate search with its own allowlist. Slack answers and drafts recheck membership, source permissions and exact evidence before delivery. Mocked tests cover provider boundaries. The four reviewed text-AI paths additionally passed a bounded synthetic live-model check; calendar, ATS, mail, meeting, payment, audio, enrichment and Slack operation still require their own live verification. See [provider setup](RECONSTRUCTION.md#provider-configuration).

The subsequent [source experience review](SOURCE_REVIEW.md) also validated sourcing criteria and screening draft generation against the configured model. Live sequence generation remains unverified after a transport failure around 61 seconds; its 120-second local deadline had not fired. No model or environment setting was replaced. Passing mocked-provider sequence tests does not resolve that live failure.
