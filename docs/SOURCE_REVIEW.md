# Source experience review — 12 October 2026

This review compares ArkOffer with the signed-in Metaview account supplied for inspection and the public product pages. It covers every main navigation area, but does **not** establish complete feature parity. Account setup gates, unavailable provider connections, unpublished backend behavior and source datasets prevent that conclusion.

Implementation updates after this audit are recorded in the [13 October AI and parity update](AI_PARITY_UPDATE.md). That follow-up resolves the sequence drafting defect and adds job-source creation and report construction/grouping; the source observations below remain the 12 October audit record.

## Public pages

The homepage and all eight product pages were inspected directly. ArkOffer now uses separate layouts for Sourcing (black/green), Application Review (mint), Screening (deep green), Notes (emerald texture), Outreach (teal split), Reports/Job Posts (white split) and the monospace coworker page. Homepage additions include the coworker image section, dark context section, impact overview and access controls. Navigation, product tabs, FAQs and mobile layouts have browser coverage.

The visible brand is ArkOffer as requested. Copy is original and describes local capabilities. Source customer endorsements, funding, certifications and outcome numbers are not represented as ArkOffer claims. Animations and product illustrations remain simplified. Pricing/resources/company/legal/native-download families retain the limitations recorded in [PARITY.md](PARITY.md). Public decorative asset provenance is recorded in [origins.json](../public/marketing/origins.json).

## Validation and operational boundaries

The delivery PR records the executed combined server/browser/build/format checks. Tests use isolated stores, synthetic people and mocked external providers; they check ownership, replay identities, stale sources, quotas, response validation and explicit review before shared writes or outreach. Browser checks exercise real local persistence and responsive navigation. Synthetic screenshots establish inspected layouts, not pixel equality across every source state.

The initial PR #5 validation passed 262 server tests, 50 browser tests, the production build and formatting checks. Bounded live requests using the existing configured model validated sourcing criteria and screening questions/private rubrics with synthetic inputs. Sequence drafting did not pass live verification: its connection failed after about 61 seconds before either local cancellation or its 120-second deadline fired. The available evidence does not distinguish a gateway failure from a network failure. Its editor, persistence, validation and review flow passed mocked-provider tests; live sequence generation remained unresolved in that initial delivery. The subsequent [follow-up](AI_PARITY_UPDATE.md) records its fix and successful live checks. The shared text adapter retains a 60-second default deadline and allows the sequence path a bounded 120 seconds, with no automatic retry or model substitution.

PDL discovery requires `PDL_API_KEY` and the separate `SOURCING_WORKSPACE_IDS` allowlist. New text features reuse the existing `.env` model/provider configuration; no gateway model is substituted. Live mail, audio, Slack, ATS, recording and billing still require their respective configured accounts and end-to-end verification. No source-account messages, candidate invitations, paid upgrades or external outreach were sent during this review.
